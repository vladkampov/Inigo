# 1.0 release readiness

Updated 2026-11-07. This is an evidence checklist, not a release announcement.
The [milestone](https://github.com/vladkampov/Inigo/milestone/1) tracks details.

## Blocking validation

- **Editor safety (#20, #21):** Verify a bounded supported-editor matrix on the
  signed candidate: replacement, exact guarded Undo, typing/focus changes, and
  rich-object fallback. The intermittent Codex picker and work-device focus
  reports are not proven fixed. Unsupported editors can remain copy-only, with
  clear documentation; universal compatibility is not a 1.0 requirement.
- **Fresh installation (#22):** Complete onboarding, permissions, model download,
  restart and offline rewriting on a fresh account/second supported Mac. Prior
  successful launch reports do not prove this whole flow.
- **Recovery and quality (#23–#25):** Exercise live model errors, cancellation,
  representative long drafts and memory pressure. Confirm keyboard navigation,
  VoiceOver, reduced motion and RTL on the actual app. Human review must cover
  representative writing and translations; narrow quality claims where review
  is unavailable rather than claiming equal quality across every language.
- **Release candidate (#26, #28):** Build/sign/notarize the actual final commit,
  review advisories and privacy boundaries, verify its archive, and test stable
  installation/update routing. Beta.6 → beta.7 is verified; beta-to-stable
  migration is not. The stable feed becomes live only with a reviewed published
  stable release. Do not publish a beta artifact under a stable label.

## Evidence already available

- Protected-main CI, Developer ID signing/notarization and public beta downloads.
- Real Sparkle beta.6 → beta.7 download, install and relaunch with preferences retained.
- Separate stable/beta feed publication with rollback and same-build guards.
- Automated editor-policy, clipboard ownership, Unicode/readback, download-integrity
  and cancellation/recovery regressions. These do not replace live editor tests.
- No open GitHub Dependabot or secret-scanning alerts at the 2026-11-07 check;
  this is not an exhaustive security audit.

## Not blockers

No App Store listing, dedicated email address, analytics, reporting provider,
website, or new feature is required. Reporting stays on GitHub. Optional error
uploads remain disabled. Imported local models and external local servers retain
explicit trust limitations. Broad human localization review can continue after
release if unreviewed coverage is disclosed accurately.

## Assistance needed

A tester with a second Mac/fresh account; human language review; and, if possible,
a synthetic reproduction on the affected work laptop. Never include workplace
writing, bypass managed security controls, or erase existing user preferences to
perform these checks. Other local and automated checks can continue independently.
